\# Workflow — техническая документация



Техническое описание проекта: как запускать, как обновлять переводы,

как проверять результат. Для витрины портфолио — см. `../README.md`.



Пути к файлам указаны относительно корня проекта.



\## Что не показывается пользователю



В публичной версии игры не видны:



\- `meta.json` — технические пометки по строкам;

\- `export/strings.csv` — рабочий файл обмена с переводчиком.



Это инструменты, а не результат.



\## Запуск



Статика без сборки, но `fetch()` не работает из `file://`. Нужен

локальный сервер:



&#x20;   python3 -m http.server 8000



Открыть `http://localhost:8000`.



\## Языки



\- `en` — source, правится напрямую в `locales/en.json`.

\- `ru` — целевой, импортируется из CSV.

\- `zh-Hans` — целевой, импортируется из CSV.



Переключатель языка — в правом верхнем углу. Выбор сохраняется

в `localStorage`, можно задать через URL: `?lang=ru`.



\## URL-параметры



| Параметр | Значение | Что делает |

|---|---|---|

| `lang` | `en` / `ru` / `zh-Hans` | Язык при загрузке |

| `coins` | целое ≥ 0 | Сколько монет в сундуке |

| `debug` | `keys` | Вместо текста — ключи |

| `debug` | `pseudo` | Псевдолокализация (+35 %, диакритика) |

| `debug` | `overflow` | Подсветка строк, вышедших за `max\_length` |

| `debug` | комбинируется: `?debug=keys,overflow` | |



\### Проверка чисел



&#x20;   ?coins=1    → 1 монета

&#x20;   ?coins=2    → 2 монеты

&#x20;   ?coins=5    → 5 монет

&#x20;   ?coins=21   → 21 монета

&#x20;   ?coins=101  → 101 монета



Для китайского — всегда `other`: `N枚金币`.



\## Файлы



\- `locales/en.json` — английский source. Правится напрямую.

\- `locales/ru.json` — русский перевод. Обновляется через `import.js`.

\- `locales/zh-Hans.json` — китайский перевод. Обновляется через `import.js`.

\- `meta.json` — контекст и технические пометки по строкам.

\- `scripts/export.js` — собирает CSV для перевода.

\- `scripts/import.js` — импортирует CSV обратно.

\- `scripts/scaffold.js` — генерирует пустую локаль с `\[TODO: <key>]`.



\## Workflow



\### 0. Английский source



Правится напрямую в `locales/en.json`. Ключи не менять.



\### 1. Экспорт



&#x20;   node scripts/export.js



Получишь `export/strings.csv` с колонками:



&#x20;   key, source\_en, context, max\_length, placeholders,

&#x20;   translation\_ru, translation\_zh



Колонки `key`, `source\_en`, `context`, `max\_length`, `placeholders` —

только для справки. Заполняются `translation\_ru` и `translation\_zh`.



\### 2. Перевод



Открыть CSV в Excel / Google Sheets / CAT.

Заполнить `translation\_ru` и `translation\_zh`.

Плейсхолдеры `{name}`, `{amount}`, `{item}` должны остаться в переводе.



\### 3. Импорт



&#x20;   node scripts/import.js ru

&#x20;   node scripts/import.js zh-Hans



`import.js` валидирует:

\- плейсхолдеры не потеряны и не добавлены лишние;

\- если перевод пуст — подставит `\[TODO: <key>]` и предупредит;

\- при ошибке в плейсхолдерах файл локали \*\*не перезаписывается\*\*.



\### 4. Проверка



Открыть `http://localhost:8000/?lang=ru` и `?lang=zh-Hans`.

Пройти сценарий.



\## Критерии приёмки



\- \[ ] EN ↔ RU ↔ ZH переключается без перезагрузки.

\- \[ ] В `app.js` нет пользовательского текста.

\- \[ ] `?coins=1|2|5|21|101` даёт корректные формы в RU.

\- \[ ] ZH не падает на отсутствующих формах множественного числа.

\- \[ ] `node scripts/import.js ru` падает на битом плейсхолдере.

\- \[ ] Ни одна реплика не потеряла смысл и интонацию при переводе.



\## Добавить новую локаль



1\. `node scripts/scaffold.js <lang>`

2\. Добавить `{ code, label }` в массив `LOCALES` в `app.js`.

3\. Готово.
